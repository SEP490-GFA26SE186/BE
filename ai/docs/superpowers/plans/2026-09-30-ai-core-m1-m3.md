# AI Core Service M1→M3 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> Plan này **cố ý không viết sẵn code** (yêu cầu của người làm). Mỗi task mô tả file, interface,
> hành vi và từng case test bằng lời; người thực hiện tự viết code theo TDD.

**Goal:** Dựng lại `BE/ai/` theo `docs/`: khung service với bốn endpoint chạy mock (M1), spike
Gemini, tiện ích tất định + validator đủ bảng `docs/04` (M2), và sinh truyện thật qua Gemini có vòng
thử lại (M3) — khớp hợp đồng mà phía Node đã cài.

**Architecture:** FastAPI stateless. Endpoint chỉ `raise AiError`, một exception handler duy nhất
dựng thân lỗi. Provider, Storage, Settings đi qua dependency của FastAPI nên test thay bằng
`app.dependency_overrides`. Logic sinh truyện dồn vào `app/core/` (hàm thuần + orchestrator nhận
provider tiêm vào); validator là registry luật có `doc_row` để test phủ bảng `docs/04`. Provider LLM
làm đúng một việc: gửi các lượt, trả chữ thô + token.

**Tech Stack:** Python (venv hiện có là 3.14; Docker là 3.12 — code phải chạy được trên 3.12),
FastAPI, Pydantic v2, pydantic-settings, httpx, `google-genai`, PyYAML, pytest + pytest-asyncio,
respx.

**Spec:** `BE/ai/docs/superpowers/specs/2026-09-28-ai-core-m1-m3-design.md` (gọi tắt: **spec**;
đã gồm mục 3.11 — tám quyết định bổ sung). Phía Node: `BE/api/docs/superpowers/plans/2026-09-30-story-generation-node.md`
(gọi tắt: **plan Node**) — **đã làm xong**, plan này chỉ kiểm tương thích.

## Global Constraints

- **Không commit, không `git add` / `stash`.** "Implement" chỉ là sửa file. Cuối mỗi task là bước
  "Checkpoint" — chạy test, báo kết quả, dừng cho người review.
- **Python:** dùng venv có sẵn `BE/ai/.venv`. Chạy mọi lệnh bằng `.venv/Scripts/python -m …` từ
  `BE/ai` (ví dụ `.venv/Scripts/python -m pytest`, hiện xanh 13 test). **Không** gọi
  `.venv/Scripts/pytest.exe` / `uvicorn.exe`: venv được tạo ở `BE/services/ai/.venv` rồi chuyển chỗ,
  các launcher `.exe` trỏ sai đường dẫn và im lặng không chạy.
- **Cài dependency:** `uv` **không** có trên PATH. Cài bằng `.venv/Scripts/python -m pip install <gói>`
  **và** thêm gói vào `pyproject.toml` (runtime vào `dependencies`, dev vào `[dependency-groups] dev`).
  Trong venv có sẵn `.venv/Scripts/uv.exe` (0.12.x): chỉ dùng nó để chạy `lock` cập nhật `uv.lock`
  sau khi sửa `pyproject.toml` (Dockerfile cài từ `uv.lock`); **không** chạy `uv sync` trên venv này.
- **Test không bao giờ gọi mạng.** Fixture chặn mạng (Task 1) cưỡng chế. Ngoại lệ duy nhất là
  `scripts/try_story.py --confirm` — **không** thuộc pytest.
- **Gemini thật:** `GEMINI_API_KEY` có trong `BE/ai/.env` (file này **chỉ** có biến đó — không có
  `INTERNAL_TOKEN`, không có `GEMINI_TEXT_MODEL`). Chỉ Task 8 (spike) và Task 14 được gọi Gemini thật,
  **ít lời gọi** (mỗi lần chạy script in số lời gọi + chi phí ước tính trước khi gọi). Kết quả ghi
  vào `docs/01-decisions.md`.
- **pytest không được đọc `BE/ai/.env`** (có API key thật): Settings trong test dựng với env file tắt,
  `LLM_PROVIDER=mock`, `TTS_PROVIDER=mock` đặt tường minh trong `conftest.py`.
- **`google-genai`:** trước khi viết `GeminiLLMProvider`, đọc tài liệu SDK **hiện hành** (bản cài
  trong venv — xem docstring / source của gói đã cài, và tài liệu chính thức) để lấy tên thật của: client
  async, cấu hình generate (schema, mime type, temperature, max output tokens, thinking, safety),
  tuỳ chọn retry/timeout HTTP, `usage_metadata` (gồm token thinking), enum `finish_reason`,
  `prompt_feedback`, các lớp lỗi. Không dựa vào trí nhớ. Khác với spec/docs → tin tài liệu chính
  thức, ghi khác biệt vào `BE/ai/README.md`.
- Wire JSON **snake_case**; mọi request model `extra="forbid"` (kể cả model lồng nhau).
- Code, tên biến, comment, log: **tiếng Anh**. `Issue.detail`, `message` lỗi trả Node, prompt: **tiếng
  Việt** (ngoại lệ có chủ ý, spec §7.2 — ghi chú tại chỗ).
- **Không log** tên thật, `forbidden_terms`, chữ gửi TTS, dữ liệu ảnh, API key, nội dung truyện ở
  INFO (DEBUG thì được, spec §8.5). Thông báo lỗi validate request **không** lặp lại giá trị đầu vào
  (Pydantic đưa `input` vào lỗi — bỏ nó đi, chỉ giữ `loc` + `msg`).
- Không viết cứng tên model, giá, giới hạn độ dài — lấy từ `Settings` hoặc request.
- Mã lỗi & HTTP đúng spec §4.3: `INVALID_INPUT` 422 (code cũ trả 400 — đổi), `FORBIDDEN_TERM_DETECTED`
  422, `SAFETY_BLOCKED` 422, `OUTPUT_INVALID` 502, `PROVIDER_ERROR` 502, `TIMEOUT` 504.
- Hợp đồng với Node (đã cài, **không sửa phía Node**): Node gửi payload snake_case do
  `api/src/modules/stories/lib/aiRequest.js` dựng; đọc lỗi ở `body.error.{code,message,retryable}`;
  gửi `__force` ở **cấp cao nhất** của body (chỉ ngoài production); đọc `usage.{provider, model,
  input_tokens, output_tokens, estimated_cost_micros}` khi thành công.

## Điều chỉnh so với spec (phát hiện khi lập plan)

1. **`guards` kéo vào M1.** Spec §2 xếp `guards` vào M2, nhưng §5.6 đòi hai endpoint ảnh chạy
   `assert_no_forbidden_terms` "ngay từ M1". Làm `guards` ở Task 3 (M1); M2 chỉ còn `split_sentences`
   + validator. Không đổi thiết kế, chỉ đổi thứ tự.
2. **`estimate_max_output_tokens` và `app/core/prompt.py` có từ M1.** Endpoint truyện ở M1 cần một
   trần token và một prompt để gửi mock. Task 5 viết hàm trần token (spec §8.1, đủ luôn phần thinking)
   và bộ render prompt (`string.Template` + front matter, spec §9.4) với `prompts/story.v1.md` bản
   khung; spike (Task 6) viết nội dung thật. `app/core/prompt.py` là file mới so với cây §4.2.
3. **Orchestrator M1 là bản tạm:** một lời gọi, không validator, không thử lại. `finish_reason =
   MAX_TOKENS`, parse hỏng hoặc map hỏng → `OUTPUT_INVALID` (kèm `usage`). Task 12 thay bằng bản đầy đủ.
   Vì vậy `__force: INVALID_OUTPUT_ONCE` chỉ ra kết quả đúng (thành công ở lần 2) từ Task 12 — trước
   đó nó ra `OUTPUT_INVALID`.
4. **Output "sai" của mock là chữ không parse được** (JSON bị cắt, `finish_reason = STOP`), không
   phải JSON thiếu trang: như vậy `__force: OUTPUT_INVALID` cho đúng kết quả ở cả M1 (chưa có
   validator) lẫn M3 (đi đường `OUTPUT_SCHEMA_INVALID` → thử lại → vẫn sai).
5. **Hàm sinh output hợp lệ dùng chung:** `MockLLMProvider` và fixture `valid_output(frame)` (spec
   §10.1) cùng gọi một hàm `build_valid_output(frame)` trong `app/providers/llm/mock.py`. Một nguồn
   sự thật cho "output hợp lệ với khung bất kỳ"; test "mọi rule đạt trên `valid_output`" (Task 9) giữ
   cho nó đúng.
6. **`generate_story` nhận thêm `settings`** (cần `TOKENS_PER_WORD`, nhiệt độ, giá…): chữ ký là
   `generate_story(req, llm, settings)` thay vì `generate_story(req, llm)` ở spec §8.
7. **Tên `Warning` trong spec §5.1 đổi thành `OutputWarning`** — `Warning` che builtin của Python.
   Wire không đổi (`{code, target_id, detail}`).
8. **PyYAML thêm vào dependency runtime** (đọc `content_rules.yaml`); hiện chỉ có mặt gián tiếp qua
   `uvicorn[standard]`. Đã sửa spec §4.5.
9. **`docker-compose.yml` (khối `ai`) và `BE/.env.example` còn `AI_PROVIDER`** — Settings mới không
   đọc biến này nữa. Sửa ở Task 16. Đã thêm dòng vào spec §12.
10. **Kiểm `request_id` (ảnh/TTS) và `portrait_key`** cùng luật với `storage_prefix`, vì cả hai đều
    thành đường dẫn file (ghi / đọc). Đã sửa spec §5.6.
11. **`BE/ai/CLAUDE.md` mâu thuẫn spec ở ba chỗ** — "Không làm: upload lên storage (ảnh và audio trả
    về base64)", "chạy `assert_no_forbidden_terms` … trên mọi output", và cây thư mục có
    `core/validator.py` (spec: package `core/validator/`). Plan **không** sửa `CLAUDE.md`; Task 15
    liệt kê ba chỗ đó trong báo cáo để người quyết định sửa.
12. **Chọn model Gemini là quyết định chưa có.** `GEMINI_TEXT_MODEL` chưa đặt ở đâu. Task 8 liệt kê
    model khả dụng, đề xuất một model chữ, **dừng hỏi** trước khi ghi vào `docs/01`.

## Review Focus

Các tình huống spec ngụ ý mà dễ bị bỏ sót nhất — mỗi dòng đã có test ở task sở hữu:

1. **Fallback `DOWNGRADE`** (spec 3.11.1) — lần 1 chỉ lệch độ dài, lần 2 làm mất một `page_id` →
   trả **output lần 1** kèm warning, không `OUTPUT_INVALID`; `usage` cộng hai lần; không lẫn warning
   của lần 2. → Task 12.
2. **Cắt cụt khi có thinking** (spec 3.11.4) — `finish_reason = MAX_TOKENS` ra `OUTPUT_TRUNCATED`
   chứ không `OUTPUT_SCHEMA_INVALID`; lần 2 gửi trần chữ × 1.5 (làm tròn lên) **cộng** budget thinking
   giữ nguyên; JSON hỏng mà `STOP` thì lần 2 giữ nguyên trần. → Task 12.
3. **`__force` khi provider không phải mock** (spec 3.11.7) — `LLM_PROVIDER=gemini` + `__force` → 422
   `INVALID_INPUT` và provider **không hề được gọi**; `__force` nằm trong object con (kiểu phong bì
   cũ) → `INVALID_INPUT` vì field lạ. → Task 5.
4. **`storage_prefix` / `portrait_key` bẩn và job chạy lại** (spec 3.11.5) — `a/../b`, `/abs`,
   `a\b` → `INVALID_INPUT`, không file nào được ghi hay đọc; cùng request gửi hai lần → cùng key, thư
   mục chỉ có đúng một file. → Task 4.
5. **Chặn mạng không làm vỡ event loop trên Windows** (spec 3.11.6) — tạo event loop mới và chạy một
   coroutine vẫn được; kết nối tới IP công khai / tên miền thật ném ngay. → Task 1.
